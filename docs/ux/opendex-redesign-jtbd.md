# Opendex Redesign — Jobs to be Done

## Usuarios asumidos
- CTOs, founders técnicos y platform engineers de SaaS en México/LATAM.
- Nivel técnico medio-alto; comparan Opendex contra Auth0, Clerk, Stripe, Firebase, PACs y POS tradicionales.
- Uso principal: desktop durante evaluación, demo comercial o integración técnica.

## Job Statement
When estoy evaluando infraestructura crítica para mi SaaS, I want to entender rápidamente si Opendex puede cubrir identidad, facturación fiscal y POS con confianza enterprise, so I can decidir si lo pruebo sin sentir riesgo técnico, fiscal o comercial.

## Solución actual y dolores
- Current: Combinar Auth0/Clerk + PAC fiscal + POS separado + integraciones internas.
- Pain: Demasiados vendors, experiencias inconsistentes, costos dispersos y baja visibilidad operativa.
- Consequence: Más tiempo de integración, más superficie de fallos y demos menos convincentes para stakeholders.

## Principios del rediseño
1. Producto antes que marketing: mostrar consola, eventos, métricas y controles reales.
2. Confianza enterprise: dark UI sobria, contraste fuerte, estados operativos y claims verificables.
3. Developer-first: código real, lenguaje técnico, rutas claras a documentación.
4. Marca diferenciada: usar el logo oficial y una paleta negra con azul eléctrico y rojo de acento.
